## Introduction

เซิร์ฟเวอร์เฉพาะ Palworld อาจล้มเหลวได้จากหลายสาเหตุ เช่น การอัปเดต Steam ล้มเหลว เวอร์ชันไม่ตรงกัน ปัญหาความขัดแย้งของม็อด และปัญหาการเชื่อมต่อ Steam ชั่วคราว ในคู่มือนี้ คุณจะได้เรียนรู้วิธีระบุปัญหาเซิร์ฟเวอร์ Palworld ทั่วไปบน ZAP-Hosting และแก้ไขอย่างถูกต้อง รวมถึงเมื่อใดที่ต้องแก้ไขไฟล์คอนฟิก ตรวจสอบไฟล์ หรือรีสตาร์ทเซิร์ฟเวอร์ของคุณ

![](https://screensaver01.zap-hosting.com/index.php/s/SCREENSHOT_PLACEHOLDER/preview)

## Preparation

ก่อนเริ่มแก้ไขปัญหา ให้แน่ใจว่าคุณสามารถเข้าถึงการจัดการเซิร์ฟเวอร์เกม Palworld และคอนโซลในเว็บอินเทอร์เฟซของ ZAP-Hosting ได้

คุณควรเตรียมสิ่งต่อไปนี้ไว้ด้วย:

| ความต้องการ | เหตุผลที่ต้องใช้ |
| --- | --- |
| การเข้าถึงแผงควบคุมเซิร์ฟเวอร์เกม ZAP-Hosting | จำเป็นสำหรับการหยุด เริ่ม ติดตั้งใหม่ และแก้ไขไฟล์คอนฟิก |
| การเข้าถึงคอนโซลเซิร์ฟเวอร์ | มีประโยชน์สำหรับตรวจสอบว่าเซิร์ฟเวอร์ตอบสนองหรือไม่ |
| สำรองข้อมูลล่าสุด | แนะนำก่อนเปลี่ยนไฟล์หรือถอดม็อด |
| ที่อยู่ IP และพอร์ตเซิร์ฟเวอร์โดยตรง | จำเป็นเพราะรายการเซิร์ฟเวอร์ล่าสุดในเกมอาจไม่เสถียร |

:::caution สร้างสำรองข้อมูลก่อน
หากคุณวางแผนจะถอดม็อด ติดตั้งไฟล์ใหม่ หรือรีเซ็ตส่วนใดของการตั้งค่าเซิร์ฟเวอร์ Palworld ควรสร้างสำรองข้อมูลก่อนเพื่อป้องกันการสูญหายของข้อมูลโดยไม่ตั้งใจ
:::

## การเข้าถึงไฟล์คอนฟิก Palworld

ขั้นตอนแก้ไขปัญหาบางอย่างต้องแก้ไขไฟล์คอนฟิก Palworld ด้วยตนเอง บน ZAP-Hosting คุณสามารถเข้าถึงไฟล์เหล่านี้ได้ผ่านการจัดการเซิร์ฟเวอร์เกมในส่วน `Configs`

สำหรับเซิร์ฟเวอร์เฉพาะ Palworld การตั้งค่าเซิร์ฟเวอร์หลักมักจะเก็บไว้ในไฟล์นี้:

```text
Pal/Saved/Config/LinuxServer/PalWorldSettings.ini
```

ถ้าเซิร์ฟเวอร์ของคุณใช้เทมเพลตแพลตฟอร์มอื่น ชื่อโฟลเดอร์อาจแตกต่างกัน แต่บนเซิร์ฟเวอร์ Palworld ที่โฮสต์บน Linux เส้นทาง `LinuxServer` เป็นตำแหน่งมาตรฐาน

### เปิดไฟล์คอนฟิกในอินเทอร์เฟซ ZAP

วิธีเข้าถึงไฟล์:

1. เปิดเซิร์ฟเวอร์ Palworld ของคุณในเว็บอินเทอร์เฟซ ZAP-Hosting
2. ไปที่ส่วน `Configs`
3. เปิดไฟล์ `PalWorldSettings.ini`
4. ตรวจสอบบรรทัด `OptionSettings=(...)` ซึ่งมีการตั้งค่าการเล่นเกมและการเชื่อมต่อส่วนใหญ่

![](https://screensaver01.zap-hosting.com/index.php/s/SCREENSHOT_PLACEHOLDER/preview)

:::info ไฟล์คอนฟิกหลัก
ตัวเลือกเซิร์ฟเวอร์ Palworld ส่วนใหญ่เก็บใน `PalWorldSettings.ini` โดยปกติจะอยู่ในส่วน `OptionSettings=(...)` หากคุณต้องการปรับการตั้งค่าเกม รหัสผ่าน ขีดจำกัดผู้เล่น หรือค่าที่เกี่ยวกับเครือข่าย นี่คือไฟล์ที่คุณจะแก้ไข
:::

### บันทึกและรีสตาร์ทหลังแก้ไข

หลังจากเปลี่ยนค่าคอนฟิกใด ๆ:

1. บันทึกไฟล์ในส่วน `Configs`
2. รีสตาร์ทเซิร์ฟเวอร์ Palworld จากอินเทอร์เฟซ ZAP-Hosting

Palworld ไม่รองรับการใช้การเปลี่ยนแปลงคอนฟิกแบบสด ดังนั้นจึงต้องรีสตาร์ทหลังแก้ไข `PalWorldSettings.ini`

## แก้ไขปัญหาการอัปเดต Steam ล้มเหลว

ปัญหาการอัปเดตที่รู้จักอาจแสดงข้อความนี้:

```text
Error! app '2394010' state is 0x6 after update job
```

โดยปกติหมายความว่าไฟล์เซิร์ฟเวอร์ Steam ของ Palworld ไม่ได้รับการอัปเดตอย่างถูกต้อง

### วิธีแก้แนะนำ

เพื่อแก้ไข:

1. หยุดเซิร์ฟเวอร์ Palworld ของคุณ
2. เปิดส่วนจัดการเซิร์ฟเวอร์ในอินเทอร์เฟซ ZAP-Hosting
3. ใช้ฟังก์ชันติดตั้งใหม่หรือยืนยันไฟล์
4. เลือกตัวเลือกตรวจสอบความสมบูรณ์เพื่อให้ไฟล์เซิร์ฟเวอร์ถูกตรวจสอบและดาวน์โหลดใหม่ถ้าจำเป็น
5. เริ่มเซิร์ฟเวอร์อีกครั้ง

:::tip ตรวจสอบความสมบูรณ์ไฟล์ที่เสียหาย
การตรวจสอบไฟล์เป็นขั้นตอนแรกที่ปลอดภัยที่สุด เพราะมันซ่อมแซมไฟล์เซิร์ฟเวอร์เกม Palworld ที่หายหรือเสียหายโดยไม่ต้องอัปโหลดไฟล์เอง
:::

### ต้องแก้ไขไฟล์คอนฟิกไหม?

โดยปกติไม่ต้องแก้ไขไฟล์คอนฟิกด้วยตนเองสำหรับข้อผิดพลาดนี้ ปัญหามักเกิดจากไฟล์เกมเสียหายหรือไม่สมบูรณ์ ไม่ใช่การตั้งค่าใน `PalWorldSettings.ini` ผิดพลาด

## แก้ไขปัญหา "Connection Timed Out"

ถ้าคุณได้รับข้อผิดพลาด `Connection timed out` ขณะเข้าร่วมเซิร์ฟเวอร์เกม Palworld สาเหตุอาจมีหลายอย่าง

## ตรวจสอบว่าเซิร์ฟเวอร์กำลังทำงานจริงหรือไม่

ก่อนอื่น ให้ยืนยันว่าเซิร์ฟเวอร์เริ่มทำงานอย่างถูกต้อง

### ใช้คอนโซล

เปิดคอนโซลเซิร์ฟเวอร์ในอินเทอร์เฟซ ZAP-Hosting และตรวจสอบกิจกรรมการเริ่มต้นปกติ ถ้าคอนโซลใช้งานได้ ให้ลองใช้คำสั่งง่าย ๆ เช่น:

```text
info
```

ถ้าเซิร์ฟเวอร์ตอบสนองปกติ แสดงว่าเซิร์ฟเวอร์กำลังทำงาน ถ้าไม่มีการตอบสนองหรือกระบวนการหยุดทำงานซ้ำ ๆ อาจหมายความว่าเซิร์ฟเวอร์ล้มเหลวระหว่างเริ่มต้น

### ตรวจสอบการใช้ทรัพยากร

ถ้า CPU ใช้งานต่ำผิดปกติระหว่างเริ่มต้นและเซิร์ฟเวอร์ไม่ตอบสนองในคอนโซล อาจหมายความว่าโปรเซสเซิร์ฟเวอร์ Palworld ล้มเหลวหรือล้มเหลวในการเริ่มต้น

| อาการ | สาเหตุที่เป็นไปได้ | การดำเนินการแนะนำ |
| --- | --- | --- |
| ไม่มีการตอบสนองจากคอนโซล | เซิร์ฟเวอร์ล้มเหลวตอนเริ่มต้นหรือโปรเซสค้าง | รีสตาร์ทเซิร์ฟเวอร์และตรวจสอบการเปลี่ยนแปลงล่าสุด |
| การใช้ CPU ต่ำมากตอนเริ่มต้น | เซิร์ฟเวอร์ไม่เริ่มทำงานถูกต้อง | ตรวจสอบม็อด อัปเดตล่าสุด และบันทึก |
| เซิร์ฟเวอร์เริ่มแต่ผู้เล่นเชื่อมต่อไม่ได้ | ปัญหาวิธีเชื่อมต่อหรือเวอร์ชันไม่ตรงกัน | ใช้ IP ตรงและตรวจสอบเวอร์ชัน |

## เชื่อมต่อโดยใช้ IP ตรงแทน Recent Servers

ปัญหาทั่วไปของ Palworld คือการเข้าร่วมผ่านแท็บ `Recent Servers` ในเกมอาจล้มเหลวแม้เซิร์ฟเวอร์ออนไลน์อยู่

ให้ใช้การเชื่อมต่อโดยตรงแทน:

1. คัดลอก IP และพอร์ตเซิร์ฟเวอร์จากอินเทอร์เฟซ ZAP-Hosting
2. ใน Palworld เชื่อมต่อโดยตรงด้วยที่อยู่นั้น
3. หลีกเลี่ยงการใช้รายการ `Recent Servers` สำหรับการทดสอบ

:::note การเชื่อมต่อโดยตรงเสถียรกว่า
ถ้าตัวเรียกดูเซิร์ฟเวอร์ Steam หรือรายการเซิร์ฟเวอร์ล่าสุดของ Palworld ทำงานไม่เสถียร การเชื่อมต่อ IP ตรงเป็นวิธีที่ดีที่สุดในการยืนยันว่าเซิร์ฟเวอร์ของคุณเข้าถึงได้
:::

## ตรวจสอบปัญหาม็อดหรือ UE4SS

ถ้า Palworld เพิ่งอัปเดตและเซิร์ฟเวอร์ของคุณใช้ม็อดหรือ `UE4SS` เซิร์ฟเวอร์อาจหยุดทำงานจนกว่าการดัดแปลงเหล่านั้นจะได้รับการอัปเดต

### สิ่งที่ควรตรวจสอบ

ตรวจสอบว่าคุณเพิ่งติดตั้ง:

- ม็อดเกมเพลย์
- การดัดแปลงเซิร์ฟเวอร์แบบกำหนดเอง
- `UE4SS`
- ไฟล์บุคคลที่สามอื่น ๆ ที่เชื่อมต่อกับเซิร์ฟเวอร์เกม Palworld

ถ้าปัญหาเริ่มทันทีหลังอัปเดต Steam ของ Palworld ไฟล์เหล่านี้น่าจะเป็นสาเหตุ

### วิธีแก้แนะนำ

1. หยุดเซิร์ฟเวอร์
2. สร้างสำรองข้อมูล
3. ถอดหรือปิดใช้งานม็อดหรือ `UE4SS` ที่เพิ่งเพิ่ม
4. เริ่มเซิร์ฟเวอร์อีกครั้ง
5. ทดสอบการเชื่อมต่อโดยใช้ IP ตรง

:::caution ความเข้ากันได้ของม็อดหลังอัปเดต
การอัปเดต Palworld อาจทำให้ม็อดใช้งานไม่ได้โดยไม่แจ้งล่วงหน้า ถ้าเซิร์ฟเวอร์ของคุณทำงานได้ก่อนอัปเดตแต่หยุดหลังอัปเดต ให้ทดสอบโดยถอดม็อดก่อนเปลี่ยนการตั้งค่าอื่น ๆ
:::

### ต้องแก้ไขคอนฟิกไหม?

โดยปกติไม่ต้องแก้ไขคอนฟิก มักเกิดจากไฟล์ไม่เข้ากันมากกว่าค่าภายใน `PalWorldSettings.ini`

## แก้ไขปัญหาการเชื่อมต่อ Steam

คุณอาจเห็นข้อความเริ่มต้นนี้:

```text
Connecting anonymously to Steam Public...Retrying
```

โดยทั่วไปเกี่ยวข้องกับปัญหาการเชื่อมต่อ Steam ชั่วคราว ไม่ใช่คอนฟิก Palworld เสียหาย

### ความหมายของข้อความนี้

เซิร์ฟเวอร์เฉพาะ Palworld พึ่งพาบริการ Steam สำหรับส่วนหนึ่งของกระบวนการเริ่มต้นและอัปเดต ถ้า Steam มีปัญหา ล่ม หรือบำรุงรักษาตามกำหนด เซิร์ฟเวอร์อาจเชื่อมต่อไม่ได้ชั่วคราว

โดยเฉพาะในช่วงที่มีทราฟฟิกสูงหรือช่วงบำรุงรักษาปกติของ Steam ซึ่งมักเกิดในวันอังคาร

### วิธีแก้แนะนำ

ลองทำตามนี้:

1. รอประมาณ `5` ถึง `10` นาที
2. รีสตาร์ทเซิร์ฟเวอร์
3. ทดสอบอีกครั้ง

ถ้าปัญหาเกิดในช่วง Steam ล่มกว้าง คุณอาจต้องรอจนกว่า Steam จะกลับมาใช้งานได้

### การพิจารณาอัปเดตอัตโนมัติ

ถ้าเซิร์ฟเวอร์ของคุณเจอปัญหาการอัปเดตซ้ำ ๆ ในช่วง Steam ล่ม คุณอาจพิจารณาปิดอัปเดตอัตโนมัติในตั้งค่าเซิร์ฟเวอร์จนกว่า Steam จะเสถียรอีกครั้ง

:::tip หลีกเลี่ยงช่วงอัปเดตตอน Steam บำรุงรักษา
ถ้าเป็นไปได้ หลีกเลี่ยงการบังคับอัปเดต Palworld Steam ในช่วงที่ Steam บำรุงรักษาที่รู้จัก เพื่อช่วยลดความล้มเหลวในการเริ่มต้นและการแก้ไขปัญหาที่ไม่จำเป็น
:::

### ต้องแก้ไขคอนฟิกไหม?

ไม่ต้องแก้ไขไฟล์ `PalWorldSettings.ini` หรือไฟล์คอนฟิกอื่น ๆ ด้วยตนเองสำหรับปัญหานี้

## แก้ไขปัญหา "เวอร์ชันเกมไม่เข้ากัน"

ถ้า Palworld แจ้งว่าแมตช์กำลังใช้เวอร์ชันเกมที่ไม่เข้ากัน หมายความว่าเวอร์ชันไคลเอนต์และเซิร์ฟเวอร์ไม่ตรงกัน

## อัปเดตเวอร์ชันเซิร์ฟเวอร์

เริ่มจากรีสตาร์ทเซิร์ฟเวอร์จากอินเทอร์เฟซ ZAP-Hosting ในหลายกรณีจะช่วยให้อัปเดตเซิร์ฟเวอร์เกม Palworld ล่าสุดถูกนำมาใช้

ถ้าเวอร์ชันยังไม่ตรงกัน ให้ใช้กระบวนการอัปเดตเซิร์ฟเวอร์ปกติของคุณ หากต้องการคู่มืออัปเดตเฉพาะ ให้ทำตามเอกสารอัปเดต Palworld ที่มีใน ZAP-Docs (ถ้ามี)

### ยืนยันเวอร์ชันไคลเอนต์

ตรวจสอบให้แน่ใจว่าเกม Palworld บนเครื่องคุณอัปเดตเต็มที่ผ่าน Steam แล้ว

| ส่วนประกอบ | สิ่งที่ต้องตรวจสอบ |
| --- | --- |
| เซิร์ฟเวอร์ Palworld | รีสตาร์ทและอัปเดตบน ZAP-Hosting |
| เกม Palworld บนเครื่อง | อัปเดตใน Steam |
| ม็อด | อัปเดตหรือถอดออกถ้าไม่เข้ากัน |

:::info เวอร์ชันไม่ตรงกันส่งผลทั้งสองฝั่ง
ข้อผิดพลาดนี้ไม่ได้หมายความว่าเซิร์ฟเวอร์ล้าสมัยเสมอไป ไคลเอนต์ Palworld บนเครื่องคุณอาจเป็นเวอร์ชันเก่ากว่า ดังนั้นควรตรวจสอบทั้งสองฝั่งก่อนเปลี่ยนแปลงลึก ๆ
:::

### ต้องแก้ไขคอนฟิกไหม?

โดยปกติไม่ต้องแก้ไขไฟล์คอนฟิกสำหรับปัญหาเวอร์ชันไม่ตรงกัน

## เข้าใจข้อความเริ่มต้น `steamclient.so`

ระหว่างเริ่มต้น คุณอาจเห็นข้อความคล้ายนี้:

```text
steamclient.so: cannot open shared object file: No such file or directory
```

ในหลายสภาพแวดล้อมโฮสต์ Palworld ข้อความที่เกี่ยวกับ Steam เหล่านี้จะปรากฏแม้เซิร์ฟเวอร์จะเริ่มทำงานปกติ

### ควรทำอย่างไร

ถ้าเซิร์ฟเวอร์ยังเริ่มทำงานและเข้าถึงได้ตามปกติ คุณสามารถละเว้นข้อความนี้ได้

### เมื่อเป็นปัญหา

ให้ตรวจสอบเพิ่มเติมเฉพาะเมื่อเซิร์ฟเวอร์ไม่สามารถเริ่มทำงานได้เลย และข้อความนี้ปรากฏพร้อมกับข้อผิดพลาดร้ายแรงอื่น ๆ

:::note ไม่ใช่ทุกบรรทัดข้อผิดพลาด Steam เป็นเรื่องสำคัญ
บันทึกการเริ่มต้นมักมีคำเตือนที่ไม่ร้ายแรง ให้โฟกัสว่าการบูตเซิร์ฟเวอร์เสร็จสมบูรณ์และรับการเชื่อมต่อได้หรือไม่ ไม่ใช่แค่มีคำเตือนในคอนโซลเพียงบรรทัดเดียว
:::

## แก้ไขปัญหาการเชื่อมต่อที่เกี่ยวกับโลกและกิลด์

ในบางกรณี ผู้เล่นอาจเจอปัญหาการเชื่อมต่อที่เกี่ยวกับสถานะโลกหรือกิลด์ มากกว่าปัญหาโปรเซสเซิร์ฟเวอร์เอง

ตัวอย่างที่รายงานคือเมื่อสมาชิกกิลด์ออกไป แต่ข้อมูลผู้เล่นที่เกี่ยวข้องกับกิลด์ยังผูกกับผู้เล่นออฟไลน์อยู่ ซึ่งอาจทำให้เข้าร่วมไม่ได้

### วิธีแก้ไขที่เป็นไปได้

ลองทำตามนี้ตามลำดับ:

1. ขอให้ผู้เล่นที่ได้รับผลกระทบเข้าร่วมกิลด์ใหม่ถ้าเป็นไปได้
2. รีสตาร์ทเซิร์ฟเวอร์ Palworld
3. ถ้าปัญหายังอยู่ ให้กู้คืนสำรองข้อมูลหรือวิเคราะห์ข้อมูลเซฟที่ได้รับผลกระทบอย่างละเอียด

:::danger การแก้ไขข้อมูลเซฟเสี่ยงต่อความเสียหาย
ถ้าคุณสงสัยว่าโลกหรือเซฟเสียหาย หลีกเลี่ยงการแก้ไขไฟล์ด้วยตนเองแบบสุ่มเว้นแต่มีสำรองข้อมูลล่าสุด การแก้ไขผิดพลาดอาจทำลายข้อมูลโลก Palworld ของคุณอย่างถาวร
:::

## ค่าคอนฟิกที่ควรตรวจสอบ

แม้ปัญหาในคู่มือนี้ส่วนใหญ่ไม่ได้เกิดจากการตั้งค่าผิด แต่มีค่าบางอย่างใน `PalWorldSettings.ini` ที่คุณอาจอยากตรวจสอบถ้าผู้เล่นเข้าร่วมไม่ได้ตามคาด

ค่าพวกนี้มักอยู่ในส่วน `OptionSettings=(...)`

| คีย์คอนฟิก | จุดประสงค์ | สิ่งที่ควรตรวจสอบ |
| --- | --- | --- |
| `ServerName` | ชื่อเซิร์ฟเวอร์สาธารณะ | ยืนยันว่าตั้งตาม
